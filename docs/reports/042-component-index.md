## Details

### Design

Same split as `shapes.ttl`: react (which owns the component factory) generates, the CLI loads the
built package in a child and writes the file. The child imports `package.js` (sets the package's
publish root, so `getPackageUri` is the package's), `shapes/index.js`, then `components/index.js`,
with two loader hooks: `ASSET_RESOLVE_HOOK` (new, resolves a relative asset specifier even when
the build did not copy the file, e.g. `.svg`) and the existing `ASSET_HOOK` (stubs the asset
module), unchanged. The generator recognises components by duck type (`.query` and `.shape`, a
query that `isLinkedInstance(…, QueryBuilder)` or a one-key wrapper of one), so a second copy of
react or core in the child does not matter. Canonical JSON is written by hand (sorted keys,
including integer-like keys that `JSON.stringify` would reorder).
